Smoking Ends Here campaign calculator

Campaign microsite proposal

How we can turn the smoking calculator into a public campaign tool.

The prototype already proves the idea. The next step is making it reliable, secure, on-brand, and ready for real users across web ads, social traffic, and in-person iPad use.

Recommendation Netlify + Supabase

Use GoDaddy for the web address, Netlify to publish the site, and Supabase to safely store the anonymous campaign responses.

Plain English Version

This is the version for the team: what we are making, where it lives, and what still needs deciding.

What users see

A short interactive calculator

People answer a few simple questions about social smoking. The page shows a personalised yearly total in a bold, shareable campaign style.

What we collect

Anonymous response data

We collect age range and calculator answers so the campaign can report patterns. We avoid names, emails, phone numbers, exact dates of birth, and precise addresses.

What we need

Owned accounts and sign-off

The project should be hosted from work-owned accounts, with a short privacy notice and agreement on how long data is kept.

How It Works

The technical setup is intentionally simple. Each part has one clear job.

1

User opens link

They arrive from Meta ads, organic social, QR code, or an iPad at an event.

2

Calculator runs

The page works in the browser, so it is fast and cheap to host.

3

User submits

A consent note explains what anonymous information is being saved.

4

Supabase stores it

The database stores each response so the team can analyse campaign trends.

5

Team reviews stats

We can export CSVs, build simple reports, and compare sources like Meta vs events.

Recommended Route

The main choices are practical: where the site lives, where the data lives, and what the team needs to agree before launch.

What needs agreeing

  • 1

    Final name and URL. “Smoking Wrapped” is useful as a prototype name, but the live campaign should use the agreed campaign wording.

  • 2

    Data fields. Confirm exactly what the campaign needs to measure, especially age range and broad location/area.

  • 3

    Privacy wording. Agree the short on-page privacy note, retention period, and who is responsible for the data.

  • 4

    Launch checks. Confirm the site works properly on mobile, desktop, and the event iPads before paid traffic is sent to it.

Suggested setup

  • A

    Hosting: Use Netlify to publish the site and protect the database details behind a secure submission step.

  • B

    Database: Use Supabase to store anonymous campaign responses and export the results for reporting.

  • C

    Domain: Keep GoDaddy for the web address if that is already where the domain is managed. It can point visitors to the Netlify site.

  • D

    Records: Give each response a random submission ID so records can be managed without collecting names or contact details.

Vercel Or Netlify?

Both would work. The recommendation is based on fit for this project and what is easiest to maintain.

Option Estimated cost Plain-English reason Recommendation
Vercel Pro is listed at $20/month plus usage, with developer seats listed at $20/month. For a work campaign, this should be set up as a proper team/business account. It gives us a clean way to publish the site, review changes before they go live, and keep database credentials away from the public page. Still a strong option, especially if the priority is developer workflow.
Netlify Pro is listed at $20/month for unlimited members, plus usage credits. It can do the same core job: host the site, manage custom domains, and handle a secure submission step. The unlimited members are useful for handover and wider team visibility. Use this. It is the better fit if several team members may need access now or after handover.
GitHub Pages Usually no extra hosting cost for a public static site. Good for showing prototypes, but less suitable once the site needs a safer way to submit data into Supabase. Fine for prototypes, not my first choice for launch.
GoDaddy hosting The team may already be paying for GoDaddy domain services. Useful for owning the web address, but it does not need to host the campaign site itself. Use GoDaddy for the domain/DNS only.

Data Capture

The safest route is to collect the minimum data needed for campaign insight.

Suggested fields

submission_idRandom record ID, not a personal identifier.
created_atDate and time the response was submitted.
age_rangeGrouped ages, not date of birth.
areaOptional broad area, if genuinely useful.
calculator answersThe slider/radio answers from the experience.
calculated totalsYearly total, borrowed total, packs, money, hours.
sourceMeta, iPad event, QR code, organic, etc.
consent_versionWhich privacy wording was shown at the time.

About submission IDs

A submission ID is useful and should not be a GDPR problem by itself. It is just a random label for a row in the database, like a receipt number. It helps us remove duplicates, audit records, export data, and delete a row if needed.


The key is that we should not combine it with direct identifiers like name, email, phone number, exact date of birth, full postcode, or anything else that makes the person easy to identify.
